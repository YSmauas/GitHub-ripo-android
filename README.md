# ZIP → קומיט ל-GitHub

כלי בקובץ HTML יחיד שמאפשר לדחוף שינויים ל-GitHub מהטלפון (או מכל דפדפן), בלי להיתקע עם עריכת קובץ-קובץ. מעלים ZIP עם השינויים, והכלי בונה מהם **קומיט אחד אמיתי** — או ברנץ' חדש עם Pull Request — דרך ה-API הרשמי של GitHub.

## למה זה קיים

באפליקציית GitHub לאנדרואיד ובחלק מהפתרונות הניידים אפשר רק לערוך/לדחוף קובץ בודד בכל פעם. הכלי הזה עוקף את זה: הוא בונה עץ קבצים (tree) שלם מה-ZIP ודוחף אותו בקומיט אחד, בדיוק כמו `git commit` רגיל מהמחשב.

## שימוש

1. פתחו את `github-zip-push.html` בדפדפן (לא כארטיפקט בתוך צ'אט — הכלי צריך גישה חופשית לרשת כדי לדבר עם `api.github.com`).
2. הכינו **Personal Access Token** (ראו הוראות למטה) והדביקו אותו בשדה המתאים.
3. מלאו בעלים, שם ריפו, וברנץ' בסיס (בד"כ `main`).
4. בחרו מצב:
   - **קומיט ישיר לברנץ'** — דוחף ישר לברנץ' הבסיס.
   - **ברנץ' חדש + Pull Request** — יוצר ברנץ' נפרד ופותח PR (שם הברנץ' לא יכול להכיל רווחים — למשל `update-feature`, לא `update feature`).
5. כתבו הודעת קומיט, ואופציונלית תיקיית יעד בריפו (`prefix`, למשל `src/`) אם רוצים שכל הקבצים ינחתו שם.
6. העלו קובץ ZIP. הכלי מציג את רשימת הקבצים שבתוכו, ומזהה אוטומטית אם יש תיקיית-שורש משותפת שכדאי להסיר (אפשר לשלוט בזה ידנית).
7. בטלו סימון לכל קובץ שלא רוצים לכלול בקומיט.
8. לחצו **דחיפה ל-GitHub** ועקבו אחרי הלוג ופס ההתקדמות. בסיום מקבלים קישור לקומיט (ואם רלוונטי — גם ל-PR).

## יצירת Personal Access Token

קישור ישיר: https://github.com/settings/personal-access-tokens/new

1. תנו לטוקן שם ותוקף קצר (מומלץ 7–30 יום).
2. תחת **Repository access** בחרו **Only select repositories** ובחרו את הריפו הרלוונטי בלבד.
3. תחת **Permissions → Repository permissions → Contents** שנו ל-**Read and write**.
4. אם תשתמשו במצב Pull Request, סמנו גם **Pull requests: Read and write**.
5. לחצו **Generate token** והעתיקו אותו מיד — GitHub מציג אותו פעם אחת בלבד.

## איך זה עובד מאחורי הקלעים

לכל דחיפה הכלי מבצע רצף קריאות ל-Git Data API של GitHub:

1. `GET git/ref/heads/{branch}` — שולף את ה-SHA הנוכחי של הברנץ'.
2. (במצב PR) `POST git/refs` — יוצר ברנץ' חדש מאותו SHA.
3. `POST git/blobs` — לכל קובץ בנפרד, מקודד כ-base64.
4. `POST git/trees` — בונה עץ קבצים חדש מעל העץ הקיים (`base_tree`), כך שקבצים אחרים בריפו לא נפגעים.
5. `POST git/commits` — יוצר קומיט אחד עם כל הקבצים.
6. `PATCH git/refs/heads/{branch}` — מקדם את הברנץ' לקומיט החדש.
7. (במצב PR) `POST pulls` — פותח Pull Request.

## אבטחה

- הטוקן נשמר רק בזיכרון הדף (משתנה JavaScript), לא ב-localStorage ולא בשום מקום קבוע — נעלם ברענון הדף.
- כל הבקשות הולכות ישירות מהדפדפן ל-`api.github.com`, בלי שרת ביניים.
- מומלץ להגביל את הטוקן לריפו ספציפי ולתוקף קצר, ולמחוק/לרענן אותו אם המכשיר משותף.

## מגבלות ידועות

- קבצים שנמצאים בריפו אבל לא בתוך ה-ZIP **לא נמחקים** — הכלי רק מוסיף/מעדכן את מה שבחרתם.
- שמות ברנץ' חייבים לעמוד בכללי Git (בלי רווחים, בלי `..`, בלי תווים כמו `~ ^ : ? *`).
- קבצים גדולים מאוד עלולים להיות איטיים להעלאה כי כל קובץ נשלח כ-blob נפרד לפני בניית העץ.
